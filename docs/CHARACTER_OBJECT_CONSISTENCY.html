Summary

The problem and the answer

A picture book is twelve illustrations of the same child in the same clothes, with the same friend and the same teddy bear. An image model draws each of them with no memory of the other eleven.

Every spread is a stateless render: one independent call to an image model. Held to prose alone, the model reinvented the trousers, the shoes, the species of the comfort toy and the face of the farmer on every page. Each picture was fine alone; the set did not read as one book.

The fix changed what a render is held to and how a render is accepted:

  • Each identity is an image plus a spec, built once per book and collected in a hashed manifest, the Book Bible: a character model sheet, an outfit spec read off that sheet, a sheet per personal object, a sheet per companion, and a plan for every plot object.
  • Every render gets the same labelled reference pack and prompt blocks rendered from that manifest.
  • Every render is judged with the sheets attached beside it, garment by garment and object by object, into fixed defect strings.
  • Candidates are ranked by tier, then score; blocking defects drive a bounded repair loop.
  • The finished set is judged as a set: crops from all spreads are tiled beside each sheet and outliers re-rendered.
0renders that receive another spread's picture as an identity reference
5identity reference classes in every pack: sheet, cover, objects, companion, world
4set-level checks: world gate, child / object / companion contact sheets, critical-object set
3automatic candidates one spread may buy per run, across all gates (default)
The governing rule

A stateless render can only be held to fixed inputs, and an invariant that no check enforces is an aspiration. The rest of this report is that sentence applied to the child, the outfit, the companion and the objects.

02
Diagnosis

Why twelve stateless renders drift

Before the Book Bible (ce-9), the doctrine was already right: fixed inputs, no chaining. What was wrong was how it applied to characters and objects.

Cause 1

The fixed inputs were words

Clothing rode as one sentence of garment prose; a comfort toy as a quoted noun; a companion as "Bea, a farmer". An image model weights pictures over prose, so every unpictured detail was per-spread freedom.

Cause 2

The anchor was the wrong kind of image

The approved cover is a scene with a title, and it usually crops legs and feet. The garments most prone to drift, hem lengths and shoes, had no pixels behind them.

Cause 3

Checks were lenient single-image booleans

QA asked one picture a yes/no question against text. Nothing compared pixels to pixels. Props and companions were not checked at all.

Cause 4

Repair was a blind re-roll

One render, a small repair budget, then ship. The cache marker replayed the drifted picture on every later run.

What each trait is held to now

TraitBefore ce-9Fixed input nowCheck now

Why not chain the previous spread?

Feeding each render the previous spread looks like the obvious fix. It was deleted: errors compound page by page, compositions converge, and one bad page poisons the rest. Every identity reference is fixed before the first spread renders and is the same for all twelve. Other spreads' pixels reach only the judge, in the set gates.

When no sheet can be elected

A judge rejection, an exhausted budget or a render failure pauses the book as visual_recovery_pending with saved evidence, so it can resume. identity_kit_failed is raised only when the anchor itself is missing. If the provider refuses to draw on every rung, the book renders on the cover alone with a loud advisory. An explicit regeneration opens a fresh attempt folder and budget; a plain resume replays saved outcomes.

The outfit spec

One vision read of the elected sheet returns five slots. top, bottom and footwear are required; outerwear may be null; accessories is a list of up to six.

Slot shapeoutfitLock.js

{ desc: "free text, up to 160 characters, length words mandatory",

  visibility: "seen" | "inferred",  colourHex: ["#rrggbb", … up to 3] }

Colour, cut, pattern and length all live in desc. On the sheet every required slot must be seen; an inferred slot is a derivation failure, and the spec falls back to a cover-derived one with an advisory. The slots are rendered into one sentence ("Top: … Bottom: … Footwear: …", 10 to 700 characters). That sentence is what is pinned, hashed, sent to the renderer and given to the judge. The hex values feed the colour metric. The spec is stored by the sheet's content hash under catalog-assets/outfit-locks/v3/.

The manifest and its hash

Objects

Three kinds of object, three policies

"Object consistency" is three different problems. Treating them as one caused drift in some cases and over-correction in others.

KindExamplePolicy
Personal objectThe child's comfort toy, from the profileA prop sheet and spec. Required on its declared evidence spread (missing is blocking). On every later spread it is carried as a small, subdued continuity prop (not visible is advisory). Only object_presence evidence carries; food, place and interest stay on their declared spreads.
Plot objectA route marker, a key, a mapA story-object plan with one fixed design per family, instances, and a per-spread schedule of state and visibility. Plot objects are not held to the "small and decorative" rule.
Anything elseInvented toys, gadgetsThe personal-object set is closed. The judge reports undeclared_object as an advisory.
What the renderer is told · PROPS blockillustrationGenerator.js

Carried: Carried by the child in this scene too — small, held or tucked under an arm, visually subdued (…), decorative and comforting only, never a tool, a clue, or part of the plot.

Closed set: These are the ONLY personal objects in this book — do NOT give the child other toys, gadgets, or handheld items. Story objects appear only as specified for THIS scene.

Single plot object: Exactly one instance in this scene; never duplicate it.

Group: A group of matching objects is intentional; each shares this one design. Preserve the individual roles stated in the scene.

Not in this picture: ABSENT FROM THIS PICTURE (…). Its mention or importance is not a request to draw it. Do not insert the family from its reference sheet.

The story-object plan

One text-model call reads the manuscript, the beats, the theme and any authored definitions, and returns up to six object families. The child's personal objects are passed in so the planner excludes them. The plan is elected create-if-absent under catalog-assets/story-objects/so-1/, keyed by a hash of its inputs.

Plan shape (so-1)storyObjects.js

object { id, name, aliases[≤12], critical, design { shape, material, colors, scale, features },

  instances[1–12] { id, description }, reference?, occurrences[≤12] }

occurrence { spread, instanceIds[], multiplicity: "single" | "group", state, evidence, required }

  • Grounded evidence. The manuscript and beats are cut into numbered passages. The planner cites passage ids; the worker resolves them to exact substrings. A spread whose text names an object but has no occurrence is an omission.
  • Authored designs are fixed. Changing a catalog definition's name, alias, design or criticality is rejected. Today the catalog authors one object: the route_marker of safari_6_7_watering_hole_map. Every other plot object is extracted from the manuscript.
  • Identity is separate from visibility. A moved, damaged or repaired instance keeps its id; only its state changes.
  • Field-scoped completion. Two whole-plan attempts. Once identities validate, only defective occurrence fields are completed, in batches of eight with two attempts each. A plan with a reported contradiction is never repaired, and a partial plan is never elected.
Reference contract · referenceContract.js

What kind of picture is this object's reference?

Each object carries a typed contract: kind is single, group, assembly or scene; subject is object, creature or landmark. It decides how the sheet is drawn (one object, one coherent group, one assembly with its parts, one context view), how it is judged, and whether set-level tiles are cropped to the object or show the whole spread.

Scene presence · scenePresence.js

Is the object actually in this picture?

A noun mention proves a referent, not that it belongs in the frame. One audit call marks every occurrence visible, absent, off_screen or optional, citing a manuscript passage. Absent objects leave the reference pack, get the "ABSENT FROM THIS PICTURE" line, and are judged as expected-absent. A family that is never visible gets no sheet.

Reference sheets for plot objects, and how they heal

A reference sheet is itself an AI image and can fail its own check (design_matches, representation_matches, plus text and unrelated people). Unlike a personal prop, a plot-object reference does not simply fail open. With CATALOG_REFERENCE_AUTOHEAL on (the default) it heals in a fixed order:

A re-plan may not rewrite a catalog-authored design. Re-plans are applied to copies; the original objects keep the render identities, so artwork already paid for is not re-keyed. An elected sheet is re-verified every time it is loaded.

The pack: fixed order, fixed labels

Each image is sent as REFERENCE IMAGE n — label. The label says what the image is for and, as importantly, what not to copy from it. There is no cap on the number of references.

#ReferenceLabel, abridged from the code
1Character model sheet"identity AND the complete outfit of the ONE child … Use it ONLY for who the child is and what they wear; never copy a pose, expression or the plain studio background."
2Approved cover"face, hair, skin tone, and the outfit's colours and materials are ground truth. Identity only — NEVER copy its pose, expression, camera distance, composition, or any lettering it carries."
3…Object sheetsVisible plot objects first, then declared props, then carried props: "this exact object — same object, colours, material and size whenever it appears".
…Companion sheetOnly when the companion is on this spread. Person: "the book's ONE recurring companion, a fictional person … exactly ONE of them."
…World plate"match its palette, lighting, era, materials … Do NOT copy its composition, and NEVER treat it as the scene to draw."

Without a sheet, the cover becomes reference 1, labelled "IDENTITY ANCHOR". In the embedded-text layout the pack also carries a lettering reference, which is outside this report.

The prompt blocks

Bible-mode blocksillustrationGenerator.js

  - Outfit (every garment, colour, pattern and length EXACTLY as the references and this spec; nothing added, nothing removed, never adapted to weather or activity): <outfit sentence>

The spec lives in these blocks. The older prompt sections still run in this mode, but they now point at the references instead of repeating prose, and the final checklist restates the outfit sentence once more. On bath and water spreads the outfit wording changes and the outfit check is skipped.

One signal decides whether the companion is on a spread

companionOnSpread reads the beat and the manuscript text. It fires on the companion's name as a case-sensitive whole word, or on the full type phrase case-insensitively. The world and display names are masked as whole words first, and if the child shares the companion's name only the beat counts. That one result gates the scene line, the sheet in the pack, the COMPANION block and the QA check, so they cannot disagree.

The safety ladder keeps the bible

A render steps down a rung only on a safety block: original, then sanitized (trigger words stripped from the scene text only; the blocks are rebuilt intact), then generic-safe (a calm generic scene with the blocks re-attached). A render accepted below the first rung carries a render advisory.

Variety is pinned separately

A strong identity reference pulls every spread toward its pose. A deterministic shot plan, seeded by the story fingerprint, assigns each spread a shot type and staging, so "who" and "how" are pinned by different mechanisms.

Key pathchildren-jobs/{bookId}/ ce-renders/ {STYLE_VERSION}/ {storyHash}/ spread-N.{aspect}.png

The cache key is the contract

storyHash starts from the book id and spread texts, then folds in the catalog tag and -b{bibleHash}. Any change to a sheet, a spec or the object plan therefore re-keys all twelve spreads. In recovery mode the fold is a per-spread dependency digest instead (-d…): a change to a plot-object reference then re-keys only the spreads that object appears on.

When the judge cannot answer

A missing or malformed required field does not produce a defect and does not pass silently. After one retry on the same image, the candidate is marked unchecked: it ranks below every checked candidate, no QA marker is written for it, and the render is re-checked on the next run.

Sourcemetrics.js

Measured signals

Two measurements run beside the judge. Neither raises a defect; both only move a candidate's score.

  • Garment colour. The child's bounding box is cropped and split into three height bands: 15–50% for the top, 50–85% for the bottom, 85–100% for footwear. Each band's dominant colours are compared with the slot's spec hex values. A slot fails when the closest pair is further apart than ΔE 28.
  • Identity embedding (opt-in, CATALOG_IDENTITY_METRICS=1). Cosine similarity between the child crop and the sheet. With six or more spreads, a spread more than two standard deviations from the set is reported to the contact gate as a character_rendering outlier.

  • Own bytes. Candidates are stored as .cK.png and repairs as .rPcK.png; the winner is copied to the canonical key. A rejected repair never overwrites better pixels.

Set gates: the book judged as a book

Twelve spreads that each pass against the sheet can still disagree with each other inside the tolerance. After the per-spread phase the run is judged as a set, in this order:

World gateOne call over up to twelve spreads at 1024 px, with a closed vocabulary of set breaks, including character_rendering (the child reads as a different age, proportions, outfit or hair). Up to three re-renders.
Contact-sheet gateAt thumbnail scale a shoe is invisible. So the child is cropped from every spread by its judged box and the crops are tiled beside the model sheet: 384 px tiles, four columns, the reference tile first. The same is done per object sheet, and for the companion over the spreads that expected it. Embedding outliers join here. All of it shares one budget of three re-renders, with one finding per spread.
Critical-object set checkFor each critical, non-degraded plot object visible on two or more spreads, a contact sheet beside its reference. This check fails closed: an unverified result is recorded as "Critical object set unverified", a failed one as "Critical object changes across spreads". It may re-render cached spreads, into an isolated namespace, and it re-verifies the set afterwards.

The world and contact gates re-render only spreads rendered fresh in this run; replayed renders are comparison references. A gate re-render that comes back worse (more blocking defects, or a lost verdict) is discarded and the original bytes are restored. Repair prompts are built from the closed defect names and cite the sheet's index in the re-render's own pack.

Ship policy and the QA marker

Default · the book finishes

Ship the best candidate, findings on record

When the budget is spent, a spread ships its best candidate. Blocking residuals, including critical-object failures, ride the callback as advisories with a book-level shipPolicy note. A spread with no image at all gets up to three fresh render rounds, then fails render_failed.

CATALOG_SHIP_ON_EXHAUSTION=0

Stop and attach the candidates

Any blocking residual fails the run consistency_unresolved with every scored candidate attached. An admin can promote one with /v13/pick-candidate.

Beside each render a .qa.json marker records the byte hash, QA_VERSION, the object-plan and scene-presence hashes, the verdict with its bounding boxes, and whether the render shipped unresolved. A cached render is re-checked, not trusted, when the bytes changed, the QA version moved, either object hash differs, or a critical-object failure is on record.

Case study and history

Secondary characters, and how we got here

Farmer Bea was two different women

A farm book shipped with its human guide drawn as a different person on two spreads. Both causes were general, and the fix (ce-19) treats every named recurring companion like the child.

Cause

Person companions had no pixels

Human companions were excluded from the companion sheet because the renderer forbade inventing adult faces. The two human-guide themes (38 books) rendered their guide as a bare noun: no sheet, no spec, no look check, no set gate.

Cause

The presence signal never fired

World-name masks were raw substring splits. The farm theme's display name "Farm" is a substring of "Farmer", so "Farmer Bea" became "er Bea" before the name was looked for. No companion line, block or check on any spread.

Fix

A sheet, a spec, and an explicit exception

A person companion gets a secondary-character sheet and a character spec. The COMPANION block states the spec as FIXED LOOK and explicitly allows this one fictional person against the no-other-humans rule.

Fix

One signal, checked like the child

Whole-word masks; one shared person-or-creature decision; look_match by face, age, hair, skin, build and outfit; a duplication check; and a companion contact sheet across the set.

Evolution

The early versions each fixed a symptom with more prompt text. The turning point was ce-9, which replaced words with pixels and booleans with structured verdicts.

09
Takeaways

Lessons, and what the audit found

1. Pin pixels, not adjectives

If an identity matters, give the model a picture of it and the judge a spec of it.

2. One spec for prompt and check

When the same sentence drives the render and the gate, spreads that each pass also match each other.

3. A gate can only reject

Every gate here is paired with a fixed input that makes the right result likely on the first render.

4. Compare at the scale of the defect

Crop the subject and tile the crops beside the reference.

5. Mention is not presence

A noun in the text does not mean the object is in the frame. Decide visibility explicitly, per spread.

6. Repairs speak in templates

Fixed defect strings and pinned data only; a repair is never adopted unverified.

7. References need recovery too

A pinned asset that fails its check replays that failure unless there is an ordered path out.

8. Rank by tier before score

Bonuses must never lift a blocking candidate over a clean one.

9. Hash what changes pixels

Approved art replays byte for byte; only what a change touches re-renders.
